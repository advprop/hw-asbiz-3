# RAG по финансовой отчётности

Решение домашнего задания. Условие лежит в [ЗАДАНИЕ.md](ЗАДАНИЕ.md).

## Результаты на test

141 вопрос, файл с ответами: [test_results.xlsx](test_results.xlsx).

| Метрика | Среднее |
| --- | ---: |
| `context_recall` | 0,863 |
| `context_precision` | 0,738 |
| `answer_correctness` | 0,908 |
| `time`, секунд | 8,11 |

Время считается от передачи вопроса в RAG до готового ответа, вопросы идут по одному. В него входят паузы из-за лимита ключа модели (10 запросов в минуту), поэтому при другом лимите оно будет другим.

## Как это работает

1. **Разбор PDF** (`rag/parse.py`). Текст берётся постранично через PyMuPDF. Слова собираются в строки по координатам, чтобы строка таблицы оставалась одной строкой. Страницы без текстового слоя (их 392, в том числе три отчёта целиком) распознаются через Apple Vision. Результат с `doc_id` и номером страницы лежит в `artifacts/pages.jsonl.gz`.
2. **Индекс** (`rag/index.py`). Для каждой страницы считается эмбеддинг через сервис курса. К тексту страницы добавляется строка с организацией, годом и номером страницы. Матрица лежит в `artifacts/embeddings.npy`.
3. **Поиск** (`rag/route.py`, `rag/retrieve.py`). По вопросу определяются организация и годы, поиск идёт только по отчётам этой организации, а страницы из отчёта за нужный год поднимаются выше. Страницы ранжируются по BM25 и по эмбеддингам, два списка объединяются через RRF. В модель уходят 10 страниц.
4. **Агент** (`rag/pipeline.py`). Модель `deepseek-flash` получает вопрос, список отчётов и найденные страницы. Она сама решает: ответить или попросить ещё один поиск со своим запросом и отчётом (не больше двух раз). В ответе модель называет страницы, с которых взяла факты, они и возвращаются как `context`.
5. **Оценка** (`eval/evaluator_excel.py`). Функции оценки из `eval/eval_functions.py` не менялись.

Клиенты эмбеддингов и модели (`rag/embed.py`, `rag/llm.py`) рассчитаны на работу из многих потоков: общий лимитер запросов, повторы с паузой при 429 и сбоях сети. Eval можно прервать и продолжить.

Библиотеки: `pymupdf`, `ocrmac` (только для пересборки страниц, нужна macOS), `rank-bm25`, `numpy`, `requests`, `openpyxl`, `python-dotenv`.

## Установка и запуск

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

В корне создайте файл `.env`:

```
LLM_API_KEY=ключ шлюза модели
EMB_KEY=ключ сервиса эмбеддингов
```

Разобранные страницы и индекс уже лежат в `artifacts/`, скачивать PDF и пересобирать их не нужно. Запуск оценки на test:

```bash
uv run python -m eval.evaluator_excel data/test.jsonl --output test_results.xlsx
```

Прогон идёт около 35 минут. В конце печатаются четыре средних, они же на листе «Итоги» в Excel. Если прогон прервался, его можно продолжить с того же места:

```bash
uv run python -m eval.evaluator_excel data/test.jsonl --output test_results.xlsx --resume
```

Параметр `--workers N` обрабатывает несколько вопросов одновременно. При лимите 10 запросов в минуту это не ускоряет прогон и завышает `time`, поэтому итоговый замер сделан с одним потоком.

### Пересборка страниц и индекса

Нужна только если хочется повторить всё с нуля.

```bash
python -m zipfile -e data/reports.zip data/reports
uv run python -m rag.parse    # около минуты, распознавание работает на macOS
uv run python -m rag.index    # около 70 минут из-за лимита 60 запросов в минуту
```
